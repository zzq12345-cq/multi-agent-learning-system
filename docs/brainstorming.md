# Brainstorming: 基于大模型的个性化资源生成与学习多智能体系统

## 目标

构建一个基于大模型的多智能体协作学习平台，能够：
1. 根据学生画像（知识水平、学习风格、目标）生成个性化学习路径
2. 多个专业化 Agent 协作完成教学资源生成、答疑、评估等任务
3. 实时追踪学习进度并动态调整学习计划

## 核心场景

### 用户故事
- 学生输入学习目标（如"一个月内掌握 Python 数据分析"）
- 系统自动评估当前水平（通过简短测试或对话）
- 规划个性化学习路径（知识图谱 + 难度梯度）
- 为每个学习节点生成定制化资源（讲义、练习题、代码示例）
- 学习过程中提供实时答疑和引导
- 阶段性评估并动态调整路径

## 多智能体架构

### Agent 角色设计

| Agent | 职责 | 核心能力 |
|-------|------|----------|
| Coordinator（协调者） | 任务分发、Agent 调度、冲突解决 | 意图识别、任务拆解、流程编排 |
| Profiler（画像师） | 学生能力评估、学习风格识别 | 对话式评估、知识点诊断 |
| Planner（规划师） | 学习路径规划、进度调整 | 知识图谱推理、难度梯度设计 |
| Generator（生成器） | 学习资源生成（讲义/题目/代码） | 多模态内容生成、难度控制 |
| Tutor（导师） | 实时答疑、概念解释、引导思考 | 苏格拉底式对话、错误诊断 |
| Assessor（评估师） | 学习效果评估、薄弱点识别 | 题目生成、答案评判、能力建模 |

### Agent 协作模式

```
用户请求 → Coordinator
              ├→ Profiler（评估能力）
              ├→ Planner（规划路径）→ Generator（生成资源）
              ├→ Tutor（实时答疑）
              └→ Assessor（阶段评估）→ Planner（调整路径）
```

## 技术选型

### 后端
- **语言**: Python 3.11+
- **框架**: FastAPI（高性能异步 API）
- **Agent 框架**: LangGraph（状态机式 Agent 编排，灵活度高）
- **LLM**: OpenAI 兼容接口（支持 DeepSeek / 通义千问 / GPT-4o）
- **向量数据库**: ChromaDB（轻量级，适合演示）
- **关系数据库**: PostgreSQL（生产）/ SQLite（开发）
- **缓存**: Redis
- **任务队列**: Celery（可选，用于异步资源生成）

### 前端
- **框架**: React 18 + TypeScript
- **构建工具**: Vite
- **UI 库**: Tailwind CSS + shadcn/ui
- **状态管理**: Zustand
- **实时通信**: WebSocket（Agent 对话流式输出）
- **图表**: ECharts（学习进度可视化）
- **知识图谱可视化**: D3.js / ReactFlow

### 基础设施
- **容器化**: Docker + Docker Compose
- **API 文档**: 自动生成（FastAPI OpenAPI）

## 边界与约束

### 范围内
- 完整的多 Agent 协作流程
- 至少支持 2-3 个学科领域的演示
- 个性化学习路径生成与可视化
- 实时对话式学习交互
- 学习进度追踪与数据看板

### 范围外（V1 不做）
- 移动端适配
- 多语言支持
- 视频/音频资源生成
- 社交/协作学习功能
- 付费/商业化功能

## 验收标准

1. **功能完整性**: 6 个 Agent 全部可工作，协作流程完整
2. **个性化效果**: 不同学生画像产生明显不同的学习路径和资源
3. **演示流畅度**: 7 分钟内能完整展示核心流程
4. **技术创新点**: Agent 协作策略可视化、动态路径调整算法
5. **代码质量**: 架构清晰、文档完整、可复现部署

## 差异化策略

1. **Agent 协作过程可视化** — 让评委看到 Agent 之间如何协商、分工
2. **知识图谱驱动** — 不是简单的线性课程，而是图结构的自适应路径
3. **实时反馈闭环** — 学→测→调 的完整循环，不是一次性生成
4. **多粒度资源** — 从概念讲解到代码实战，覆盖不同学习深度

## 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| LLM API 调用成本 | 演示时可能超预算 | 使用 DeepSeek（性价比高）+ 缓存策略 |
| Agent 协作不稳定 | 输出质量波动 | 结构化 prompt + 输出校验 + 重试机制 |
| 1 个月时间紧张 | 功能不完整 | MVP 优先，核心流程先跑通 |
| 知识图谱构建耗时 | 演示领域受限 | 预置 2-3 个精心设计的学科图谱 |
